# siyuan-md-sync (思源笔记 Markdown 文件夹同步插件)

把一个或多个 Markdown 文件夹**实时映射**到思源笔记本里。思源开 → 自动跑；思源关 → 自动停。不全盘扫描。

## 解决什么问题

- **AI 写了很多 .md 散在各处** → 在思源里集中查看/编辑
- **思源太重、开 N 个 tab 卡顿** → 用普通编辑器/Git 直接操作 .md
- **思源没法直接打开文件夹** → 这个插件搞定

## 工作模型

```
        chokidar 监听（hash 回声去重）
[A] 监听文件夹里的 .md  ─────────────────►  思源笔记本
                                          /inbox/foo/bar.md
[B] 思源命令"导出当前文档为 .md"  ─────►  任意 .md 路径
[C] 命令"导入 .md 文件/文件夹"   ─────►  思源
```

| 流向 | 自动 / 手动 | 范围 |
|---|---|---|
| A. fs → siyuan | **自动** | 仅用户在设置里加的监听文件夹 |
| B. siyuan → fs | 手动 | 当前打开的文档 |
| C. 任意 .md → siyuan | 手动 | 弹文件选择器，无范围限制 |

**默认不做全盘扫描，不做后台守护。** 监听范围由用户在插件设置里配置；思源关掉时一切停止。

## 安装

### 方式一：手动（开发者）

```bash
# 1. 找到你的思源工作空间路径（思源里：设置 → 关于 → 工作空间）
WORKSPACE=~/Documents/SiYuan

# 2. 把本目录放到工作空间下的 plugins/ 目录
mkdir -p "$WORKSPACE/data/plugins"
cp -R siyuan-md-sync "$WORKSPACE/data/plugins/"

# 3. 重启思源，设置 → 插件 → 找到「Markdown 文件夹同步」→ 启用
```

## 使用

1. 启用插件后，思源命令面板（`Cmd+P` / `Ctrl+P`）会出现 4 个命令：
   - **导入 Markdown 文件**——弹文件选择器
   - **导入 Markdown 文件夹**——弹文件夹选择器
   - **将当前文档导出为 .md**——把当前打开的思源文档存到任意 .md
   - **立即对账**——扫一遍所有监听文件夹
2. 打开插件设置（设置 → 插件 → Markdown 同步）：
   - 选择**目标笔记本**
   - 填写**目标 HPath**（默认 `/inbox`，监听文件夹里的 `foo/bar.md` 会被导入为 `/inbox/foo/bar`）
   - 点击「**添加监听文件夹**」，选一个或多个
3. 之后，凡是在监听文件夹里改动、新增、删除 .md，思源里都会自动同步。

## 典型用法：让 AI 工具的输出自动进思源

```bash
# 1. 建一个「drop 文件夹」
mkdir -p ~/Documents/AI-Drop

# 2. 在插件设置里把它加为监听文件夹，HPath 设为 /ai-inbox

# 3. 配置你的 AI 工具（Cursor / Claude Code / Cline 等）输出到这个目录
# Cursor：在 .cursorrules 或工作区设置里指定
# Claude Code：通过 hook 脚本：
```

Claude Code 钩子示例（写到 `~/.claude/settings.json`）：

```json
{
  "hooks": {
    "Write": [
      {
        "matcher": "*.md",
        "hooks": [
          { "type": "command", "command": "echo $CLAUDE_PROJECT_DIR" }
        ]
      }
    ]
  }
}
```

更简单：把 AI 工具的项目目录直接加为监听文件夹。

## 已知限制

1. **「导出当前文档为 .md」是手动命令**，不是自动的。原因：思源是块级模型，自动反向同步会引发"内容来回改"循环和不必要的写盘。如需自动反向，请提 issue。
2. **每个 .md 改动 = 思源端删 + 重建**。这是思源 API 限制（没有"按 HPath 更新内容"接口）。块 ID 通过 IAL 复用 `{: id="xxx"}` 标记，块引用 `((id))` 可以保持稳定。
3. **写回 IAL 会让 .md 变脏**（多出 `{: id="..." updated="..."}`）。如果介意，关掉"写回 IAL"选项，代价是块引用失效。
4. **嵌套文件夹的父级会被自动创建为空 doc**（思源 HPath 的特性），不影响使用。
5. **依赖 Node fs 权限**。思源插件默认在 Electron renderer 跑，fs 可用。如果用第三方容器化思源可能不行。

## 常见问题

**Q: 能监控 Git 仓库吗？**
A: 监听文件夹路径是绝对路径，git 工作区任意子目录都可以。Git pull/push 触发的文件改动会被 chokidar 捕获，自动同步到思源。

**Q: 我改了思源里文档的标题，会写回 .md 文件名吗？**
A: 不会。v1 文件名是绑定到监听文件夹的相对路径的，标题改动不影响路径。如需改名/移动，请直接在文件系统侧操作。

**Q: 性能如何？**
A: 1000 个 .md 文件以内的监听完全无感。10000+ 时启动会慢 1-2 秒（首轮 hash 校验）。运行期靠 chokidar 增量，单文件改动延迟 < 1s 出现在思源。

**Q: 怎么删除插件同步过的内容？**
A: 监听文件夹里删除 .md → 思源里的对应文档也会被删除（双向的删除同步是自动的）。
